# Env Vault Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Criar um cofre zero-knowledge para arquivos `.env` por projeto, separado do sync normal e acessível por API, CLI e frontend.

**Architecture:** O backend armazena apenas blobs criptografados e metadados seguros. CLI, MCP local e navegador criptografam/descriptografam com segredo individual do usuário; o segredo e o plaintext nunca saem da máquina local. O sync normal continua bloqueando `.env` e segredos.

**Tech Stack:** TypeScript, Node.js `crypto`, Web Crypto, Zod, Fastify, Drizzle/PostgreSQL, Commander, React/Vite.

## Global Constraints

- Responder, documentar e commitar em pt-BR.
- Não usar emojis em código, UI, logs, docs ou mensagens de CLI.
- Não incluir co-author em commits.
- Não alterar nem aplicar schema/DDL até receber `AUTORIZO ALTERAÇÃO DE SCHEMA PARA ENV VAULT`.
- O backend nunca deve receber plaintext de `.env`, segredo principal, recovery key em claro ou valores de variáveis.
- Env Vault não pode reutilizar `contentItems`, `clientProfileItems`, search, diff, restore nem sync genérico.
- Metadados persistíveis não podem incluir hash de plaintext nem nomes de variáveis por padrão; usar hash operacional do ciphertext.
- `.env` permanece bloqueado nos fluxos normais de `myinst push`, `myinst import`, chats, Project State e MCP sync.
- Pull de `.env` nunca sobrescreve arquivo local silenciosamente; cria backup ou exige flag explícita.
- Recovery por e-mail/2FA/passkey só autoriza a ação; não descriptografa sem material criptográfico do usuário.

**Files:**
- Create: `packages/shared/src/env-vault.ts`
- Modify: `packages/shared/src/index.ts`
- Modify: `packages/shared/package.json`
- Test: `packages/shared/tests/env-vault.test.ts`

**Interfaces:**
- Produces: `criptografarEnvVault`, `descriptografarEnvVault`, `gerarRecoveryKeyEnvVault`, `extrairMetadadosEnvSeguro`, `validarPayloadEnvVault`, `calcularHashCiphertextEnvVault`.
- Produces: tipos `EnvVaultEncryptedPayload`, `EnvVaultMetadata`, `EnvVaultKdfParams`.

- [ ] **Step 1: Write failing tests**

Cobrir:
- roundtrip de `.env` com comentários, aspas e multiline;
- segredo incorreto falha sem retornar plaintext;
- dois payloads do mesmo conteúdo têm `salt` e `iv` diferentes;
- metadados padrão não retornam nomes de chaves, valores nem hash de plaintext;
- nomes de chaves só aparecem por opt-in local após unlock;
- payload malformado ou KDF fora do padrão é rejeitado antes de derivar chave;
- recovery key é gerada com entropia suficiente e não é derivada do plaintext.

- [ ] **Step 3: Export public API**

Exportar o módulo em `packages/shared/src/index.ts` e adicionar subpath `./env-vault` no `exports` do package.
